# cook852 中式食譜網站 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Docusaurus site for Chinese recipes, written in Traditional Chinese, deployed to GitHub Pages at `https://cook852.github.io/`.

**Architecture:** A Docusaurus 3 classic-preset site in the repo root. The docs plugin is repointed from `docs/` to `recipes/`, so each recipe is one Markdown file and each category is one folder with a `_category_.json`. The blog is turned off. A small Node script checks every recipe's frontmatter and section headings, `npm run build` (with broken links set to throw) checks the site, and a GitHub Actions workflow builds and deploys to Pages on every push to `main`.

**Tech Stack:** Docusaurus 3.x (latest 3.x on npm, TypeScript template), Node 20 LTS, `@easyops-cn/docusaurus-search-local` for offline Chinese search, `node:test` for the content check, GitHub Actions (`actions/upload-pages-artifact` and `actions/deploy-pages`).

**Spec:** None. The user asked for sensible defaults, and those defaults are written into Global Constraints below.

## Global Constraints

- Site URL is `https://cook852.github.io`, `baseUrl: '/'`, `organizationName: 'cook852'`, `projectName: 'cook852.github.io'`, `trailingSlash: false`.
- i18n: `defaultLocale: 'zh-Hant'`, `locales: ['zh-Hant']`, `localeConfigs['zh-Hant'] = { label: '繁體中文', htmlLang: 'zh-Hant-HK' }`. HK flavour is my guess from the "852" in the repo name.
- All visible UI copy we write (navbar, footer, homepage, category labels, tags) is Traditional Chinese with Hong Kong vocabulary (薯仔, 番茄, 雞翼). There is no English UI text apart from the site name `cook852`.
- Recipe content lives in `recipes/`, not `docs/`. `docs/` is kept for project docs like this plan and must never be rendered.
- Recipe filenames and folder names are lowercase ASCII kebab-case (pinyin or English, e.g. `fan-qie-chao-dan.md`). Chinese appears only in `title` and in the content, so URLs are never percent-encoded.
- `onBrokenLinks: 'throw'`, `onBrokenMarkdownLinks: 'throw'`.
- Blog is disabled (`blog: false`).
- Node `>=20` is set in `package.json` `engines`, and CI uses Node 20.

### Recipe format (exact)

Frontmatter (all required except `tags` and `sidebar_position`):

```yaml
---
title: 番茄炒蛋
description: 十分鐘完成嘅家常菜，酸甜滑蛋。
servings: 2
prep_time: 5 分鐘
cook_time: 5 分鐘
difficulty: 易   # one of 易 / 中 / 難
tags: [jia-chang, ji-dan, kuai-shou]   # keys from recipes/tags.yml
---
```

Body headings, in this order: `## 材料`, `## 調味料`, `## 做法`, `## 小貼士`. `## 調味料` and `## 小貼士` are optional. `## 材料` and `## 做法` are required, and `## 做法` must be an ordered list.

Categories (folder → label → position):

| folder | label | position |
|---|---|---|
| `jia-chang` | 家常小菜 | 1 |
| `tang` | 湯水 | 2 |
| `dian-xin` | 點心 | 3 |
| `fan-mian` | 粥粉麵飯 | 4 |
| `tian-pin` | 甜品 | 5 |

## Review Focus

1. **A new recipe with a Chinese filename** produces an ugly `%E7%95%AA...` URL. `check-recipes` must reject any non-ASCII path (test in Task 2).
2. **A recipe missing a required field or heading** should fail before deploy and not render a half-empty page. `check-recipes` runs in CI before the build (tests in Task 2, wiring in Task 5).
3. **Searching a two-character Chinese term** (e.g. `雞蛋`) must return the recipe. Verified manually against the production build (Task 4).
4. **Deep links on GitHub Pages** (e.g. a reload on `/recipes/jia-chang/fan-qie-chao-dan`) must not 404. Covered by `trailingSlash: false` plus a post-deploy check (Task 5).
5. **Leftover English theme strings** in custom UI (navbar, footer, homepage, "Tags" headings). Built-in theme strings come from Docusaurus's zh-Hant translations. Our own strings are checked by grepping the build (Task 3).
